Medicaid Eligibility Automation (Excel VBA)

A set of Excel VBA tools that run Zycron's monthly Medicaid eligibility check for 47 school districts. They expand each student roster into name variations so students with hyphenated or multi-part names aren't missed, map the eligibility results back to the original roster, and flag incomplete response files before anything goes out.

Read the case study →

Background

Every month, Zycron checks which students are eligible for Medicaid, one school district at a time. Students are matched by name, and names are messy: a hyphenated or three-part name can appear in many forms, so an exact lookup quietly misses eligible students. Preparing each roster and reading the responses back by hand was slow and easy to get wrong.

What I built

  • Eligibility Automation — imports a school's roster, removes duplicates, and generates every likely form of each name (5 for two-part names, 12 for three-part names), built in memory and written in one pass so large rosters don't freeze Excel
  • Eligibility Responses — maps the results back to each student's original name using match checks and lookups, then saves the cleaned file
  • Responses Check — scans a whole folder and flags any response file with gaps in the data
  • Drop-In Automation — fills in student gender from master data across every extracted file

Result

A repeatable monthly process that has run for 47 school districts every month since April 2026, catching students an exact name match would miss and turning a manual, error-prone prep job into a few clicks. It's also where my work with Zycron started — before the web apps below.

AI-Powered PDF Prescription Name Extractor

A full-stack web app built end-to-end for a client that automatically reads scanned school-therapy prescription PDFs, extracts each student's name with AI vision, and saves clean, structured records to a database — replacing slow, error-prone manual data entry with a fast upload-and-review flow. Designed, built, and deployed solo, using AI development tools to accelerate the build.

View live app ↗ Read the case study →

Background

A school-based therapy provider received prescriptions as scanned PDF documents. To keep their records current, staff had to open each file, read every student's name, and manually retype it into their system — one page at a time. Across large batches this was slow, repetitive, and easy to get wrong, with typos slipping into important records.

Objective

Turn a manual, hours-long data-entry task into a quick, reliable process: let staff upload a scanned PDF and get accurate, structured student names back in minutes — ready to review and save — while keeping access secure and available from anywhere.

What the client needed

  • Upload scanned prescription PDFs directly through a browser
  • Automatically detect each student's name per page — even on imperfect scans
  • A quick way to review results before committing them
  • Save clean records to a searchable database
  • Secure, login-protected access
  • Hosted online so the team could use it from any location

My approach

I scoped the problem, designed the workflow and data model, and built the entire application solo — using AI development tools to accelerate the build rather than replace the thinking behind it. The app converts each PDF page into an image, then uses AI vision with structured tool-calling to read and return names reliably, with an OCR fallback for tricky scans. Progress streams back page-by-page in real time so nothing feels like a black box, and logins are secured with hashed passwords. It also connects to the client's SharePoint through Microsoft Graph and Power Automate, so files and records move between the app and their existing Microsoft 365 workflows without manual hand-offs, with daily backups to Azure Blob Storage.

For hosting, the client wanted the tool deployed on Microsoft Azure — since their operations already run there, keeping everything inside one trusted, secured cloud environment was the safer, simpler choice than introducing a new platform. I containerized the app with Docker and deployed it into their existing Azure setup, so it fits neatly within the infrastructure and security controls their team already relies on.

Result

A working, deployed tool that collapses an error-prone, hours-long manual task into a simple upload-and-review flow — saving time and cutting transcription mistakes. It now serves 47 schools, with 9,000+ pages processed so far. More broadly, it's proof of how I now work: pairing an analyst's eye for data accuracy with AI tools to deliver custom software that solves exactly what a client needs.

PDF Data Matching — Remittance vs. Billing Reconciliation

An internal web app for Zycron Industries that checks eMedNY remittance PDFs against the billing CSV export for the same school district — flagging missing rows in both directions, values that don't match, denied or pended claims, and explaining exactly why the totals do or don't reconcile. Handles one school or a whole billing cycle (~20 schools) in one batch, with downloadable Excel reports.

View live app ↗ Read the case study →

Background

Every billing cycle, Zycron receives Medicaid remittance statements as PDFs — one per school district — and has to confirm they line up with what was actually billed. Doing that by hand meant reading claim after claim off the PDF and hunting for each one in a spreadsheet export, across roughly twenty schools per cycle. Missing claims, wrong rate codes, and unexplained gaps in the totals were easy to miss.

Objective

Make reconciliation fast and trustworthy: upload the remittance and billing files, and get a clear answer on what matches, what doesn't, and why the totals differ — for one school or the entire cycle at once.

What the client needed

  • Compare each remittance PDF with its billing CSV, row by row
  • Flag missing claims on either side and fields that don't match
  • Surface denials and pends, with the reason
  • Explain the gap between billed, charged, and paid totals
  • Check a full cycle of schools in one go
  • Excel reports to fix exports and follow up on denials
  • Same secure sign-in as their other Zycron tool — patient data stays protected

My approach

I built a matching engine that pairs claims on Medicaid ID + date of service + rate code, one-to-one, so two services on the same day are handled correctly. Unmatched rows get a second pass on ID + date, so a wrong rate code shows up as a single field difference instead of two "missing" rows. Name checks allow for the truncation the PDF applies, and every gap in the totals is broken down into the reasons that add up to it — denials, pends, partial payments, and missing rows.

To make the output trustworthy, the app runs a read check: the claims parsed from the PDF must add up to the totals the PDF itself prints. If they don't, it shows a clear warning rather than a misleading comparison. In batch mode, files are paired automatically by the Medicaid IDs inside them (so renamed files still work) and confirmed by district name, with a review step before running. It ships as a Docker container on the client's existing Microsoft Azure setup, sharing sign-in with the PDF Name Extractor, and uploaded files are deleted after reading — results expire after an hour.

Result

A cycle's worth of reconciliation that used to mean hours of side-by-side checking now takes a couple of uploads: a summary table with the schools that need attention listed first, a detailed report per school, and a single Excel workbook covering the whole batch. It turned my day-to-day data-validation discipline into a tool the client's team can run themselves.
